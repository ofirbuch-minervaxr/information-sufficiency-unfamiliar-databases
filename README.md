# Recognizing Sufficiency in Unfamiliar Databases

Course project (LLM / GenAI) - Gilad Kogan & Ofir Buchshtab

**Main research question:** can synthetic training data improve an LLM's ability to detect whether the available information is sufficient to answer a question about an unfamiliar database?

## Project motivation
Organizations depend on poorly documented databases, and the original developers are often unavailable. LLMs can help, but they may invent missing information.

## Problem statement
Input: schema, metadata, sample records, user question.
Output: sufficiency status (sufficient / ambiguous / insufficient context / unanswerable), missing information, explanation, next action.

## Datasets used or collected
No public dataset labels "is the information enough to answer?", and real databases are private. So the training and evaluation data is **fully synthetic**, generated by the pipeline below, in several domains. A small real database is labelled by hand and used **for testing only, never for training**. Splits are by database, so test databases are never seen in training.

## Data augmentation and generation methods
1. A strong LLM generates complete, validated databases in several domains.
2. It generates questions whose answers are known from the full database.
3. We create *incomplete views*: remove column descriptions, keys, tables or sample rows.
4. The label follows by rule and execution:
   - sufficient: the answer is derivable from the given information only
   - ambiguous: two plausible readings give different results when executed
   - insufficient context: needed information was removed
   - unanswerable: the data is not in the database at all
5. Generate the structured expected response, validate (SQL runs, answers match, labels consistent), filter, split by database.

## Metrics
- Sufficiency classification: accuracy, macro-F1 over the 4 statuses, confusion matrix.
- Headline KPI: false-sufficient rate (answers given when information is missing); counter-metric: over-refusal rate.
- Calibration: expected calibration error on the reported confidence.
- Missing information: precision / recall vs. the removed items; explanation and next action: rubric-based LLM judge, spot-checked manually.
- Baselines, same metrics: zero-shot, few-shot, prompt-only, and a naive "always sufficient".
